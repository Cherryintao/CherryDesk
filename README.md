# CherryDesk

一个自用的 Windows 托盘工具，在公司 Win10 开发，主要在家里的 Win11
使用。当前版本为 0.3，包含麦克风、声音输出切换，以及 CPU/GPU/内存
性能悬浮窗。外星仔加速器暂停后关机尚未实现，界面没有真实关机入口。

## 运行和使用

开发电脑上双击 `CherryDesk.cmd` 即可构建并启动。主窗口采用左侧功能导航和右侧
设置页，配色参考 [VS Code Dark Modern](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_modern.json)，
包含音频设备、性能监控和关机助手；关机助手目前为适配说明页。窗口分别显示输出与麦克风
的当前默认设备和通信设备；在下拉框选中设备后点击切换按钮才生效。
“同时切换默认通信设备”默认勾选，取消后只修改普通默认设备。

关闭窗口会驻留任务栏托盘。双击托盘图标打开窗口，右键菜单可直接选择
输入或输出设备，也可以退出程序。设备每三秒自动刷新，接入或拔出 USB
耳机后会更新。没有可用设备时禁用切换。音频组合预设、音频快捷键和
开机自动启动尚未实现。

切换的是 Windows 默认设备。游戏或语音软件若固定选用了具体设备，
可能需要改成“系统默认设备”；部分程序不会实时跟随系统切换。不能区分
两个插在同一模拟声卡接口且由系统呈现为同一个端点的物理耳机。

## 性能悬浮窗

主窗口的“性能监控”页显示整机 CPU、所选显卡 GPU 和物理内存使用率，
内存同时显示已用与总容量（GiB）。页面右上角“启用监控”为独立总开关，
默认关闭。关闭时不会创建采集器、GPU 查询或周期采样定时器；关闭已有
监控时取消采样，等待正在进行的调用结束并释放采集器。界面清空旧数据，
隐藏悬浮窗。重新启用会创建全新采集器并重新预热，反复切换不会叠加线程。

启用后数据每秒更新，主窗口关闭到托盘或切到其他设置页时仍继续监控。
“显示悬浮窗”只控制是否显示，临时隐藏仍采集；要停止采集应关闭总开关。
Ctrl+Shift+F10/F11 不会在监控已关闭时偷偷启用采集。GPU 默认优先选择专用显存较大的硬件适配器，
也能手动选择；名称前的 GPU 编号为 DXGI 枚举顺序，不保证与任务管理器
的编号完全相同。部分机器会暴露同名的虚拟适配器，无有效计数时显示 `--`。

开启监控后，悬浮窗默认置顶、显示且锁定，鼠标会穿透到下方游戏。按
`Ctrl+Shift+F10` 显示或隐藏，`Ctrl+Shift+F11` 锁定或解锁；解锁后按住
悬浮窗拖动，完成后重新锁定。全局快捷键被占用时，主窗口会提示，仍可
使用主窗口或托盘菜单控制。“不透明度”越低越透明，“重置位置”移回主屏
工作区左上角；托盘中的重置还会重新显示悬浮窗。

监控总开关、悬浮窗显示状态、位置、锁定状态、不透明度和显卡选择保存在应用目录的
`overlay-settings.json`，采用临时文件替换方式写入。重启后恢复设置，
离屏位置在启动时调整回可见工作区。目录不可写时仍可使用，主窗口会
提示保存失败。显卡选择保存设备描述而非随重启变化的 LUID，在另一台
电脑找不到对应设备时自动回退。多个同型号适配器用枚举序号区分。
从 v0.2 升级时，旧的显示偏好会保留，但不会据此自动打开新的监控总开关。

悬浮窗为独立的 Windows 透明窗口，优先支持桌面、窗口化和无边框游戏。
独占全屏、各游戏的反作弊环境、多屏不同缩放率及家里 9070 XT 需要实测。
此版本不包含 FPS、温度或功耗。游戏内部数据和进程内存不参与采集。

## 开发环境

使用 C#、WPF、.NET 10 和少量 WinForms 托盘接口，当前只构建 x64。
固定 SDK 10.0.404，便携 SDK 放在 `.tools/dotnet`，不修改系统 PATH，
不需要安装完整 Visual Studio。首次在新电脑开发时运行
`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1`。
脚本从微软下载 SDK 并核对官方元数据中的 SHA512；这不修改系统执行策略。

在仓库根目录使用 `scripts/dev.ps1`：默认动作 `run`，也支持 `build`、
`test`、`diagnose`、`performance`、`publish`。例如 `./scripts/dev.ps1 test` 会运行
不改变真实音频设置的回归测试。`./scripts/dev.ps1 diagnose` 在
`work/audio-diagnostics.json` 输出真实设备和默认角色的只读快照。
`./scripts/dev.ps1 performance` 连续采集六次，在
`work/performance-diagnostics.json` 保存数据和采集耗时。

日常构建和测试不需要第三方 NuGet 包，`NuGet.Config` 默认清空源以便
离线还原。`publish` 为生成包含运行时的便携包，会显式访问官方 NuGet 源
下载微软 Windows x64 运行时包，输出到 `artifacts/CherryDesk-win-x64`。
可以把整个发布目录复制回家运行其中的 `CherryDesk.exe`，不需要 SDK。

已在 Win10 Pro 22H2 上完成构建、22 项回归测试、真实端点枚举、现有默认
设备写回检查及窗口/托盘启动验证。本机识别到两个输出端点，没有活动
麦克风；尚未进行不同实体设备之间的切换和听音测试。Win11 及家里的
音频设备还需要回家实测。实际可运行性与微软的操作系统维护支持范围不同，SDK 的官方支持
范围参见 [支持系统](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)。

## 实现与验证边界

`AudioSwitcher` 负责校验设备、切换所选角色、读取系统状态确认，并在
失败后尝试恢复各角色原来的设备。输入和输出相互独立。回归测试覆盖
中途失败、静默未生效、恢复失败、设备消失和通信设备选项。

`CoreAudioBackend` 枚举活动端点并读取友好名称。默认设备的设置使用
广泛用于音频切换工具的 PolicyConfig COM 接口；它不是微软承诺稳定的
公共设置接口，所以实现集中在单独模块，以便后续适配 Windows 更新。
程序只修改用户默认设备，不创建录音流、不修改游戏进程、不需要驱动。

CPU 从 `GetSystemTimes` 两次差值计算（内核时间包含空闲时间），物理
内存从 `GlobalMemoryStatusEx` 读取。CPU 口径为时间占用率，与任务管理器
按频率调整的处理器效用百分比可能不同；超过 64 个逻辑处理器的机器，
`GetSystemTimes` 有处理器组限制，本版本尚未针对这种硬件验证。
GPU 通过 DXGI 枚举，按 LUID 对应 PDH 的 `GPU Engine` 计数器；同一
物理引擎先合并各进程，再取最忙引擎，避免把不同引擎直接相加。计数器
使用语言无关名称，缺失、无效和预热中的数据均显示 `--`，不会伪装为 0%。
GPU 初始化失败后每 30 秒尝试恢复，其余指标继续更新。

公司 Intel UHD 730 上已经取得连续有效的 GPU、CPU、内存样本。
原生窗口验证包括 layered/transparent/noactivate 样式、锁定与解锁、
隐藏和恢复、不透明度。真实关闭验证会等待超过一个采样周期，确认采样
次数不再增长、活动采集器为零、旧快照清空且悬浮窗隐藏；回归测试也覆盖
关闭时的在途读取、重新开启、连续快速开关和旧设置迁移。
游戏内实际鼠标穿透与显示兼容性仍需实测。

出现错误时，日志写入应用目录下的 `logs/app.log`。诊断文件包含本机
设备名称和端点 ID。后续加速器模块需要在装有外星仔的家庭电脑上检查
客户端控件，并验证暂停状态；未确认成功前不会发起关机。

开发验证还可向程序传入 `--verify-defaults <json路径>`，逐个将现有角色
默认设备写回原值并读取确认；它不主动切到其他设备。`--smoke-test <png路径>`
会短暂启动窗口、生成托盘菜单并渲染自身 WPF 界面，再输出 PNG 和同名
JSON 状态报告后退出。截图为程序内容的渲染结果，不包含原生窗口边框。
`--overlay-smoke-test <png路径>` 会切到性能页、检查悬浮窗行为和采样，
输出主窗口 PNG、带 `-overlay` 后缀的悬浮窗 PNG、关闭状态和其他设置页
预览及 JSON 报告，并检查关闭监控后不再采样。启动检查
使用临时设置，不覆盖正常偏好；`--show-performance` 仅切换到性能页。
普通 `--smoke-test` 还验证默认启动时采样次数和活动采集器均为零。
