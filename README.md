# CherryDesk

一个自用的 Windows 托盘工具，在公司 Win10 开发，主要在家里的 Win11
使用。当前版本为 0.4，包含麦克风、声音输出切换、无线设备电量，
以及 CPU/GPU/内存性能悬浮窗。外星仔加速器暂停后关机尚未实现，界面没有真实关机入口。

## 在另一台电脑 clone 后首次运行

准备一台 Windows 10/11 x64 电脑，并安装好用于 clone 的 Git。无需预先安装
Visual Studio、.NET SDK 或 .NET 运行时。选择一个当前用户可写的目录，在 PowerShell 中执行：

```powershell
git clone https://github.com/Cherryintao/CherryDesk.git CherryDesk
Set-Location .\CherryDesk
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
.\CherryDesk.cmd
```

如果已经 clone 并进入项目根目录，只需执行最后两行，等环境准备成功后再启动。
`git clone` 只下载源码，不会执行安装或构建脚本；当前 `CherryDesk.cmd` 也不会自动下载缺失的 SDK，
所以新电脑第一次需要主动运行一次 `setup.ps1`。这个脚本会读取 `global.json` 中的 SDK 版本，
从微软下载对应的 Windows x64 SDK、校验 SHA512 并解压到项目的 `.tools/dotnet`。
首次准备需要联网和解压空间，完成后显示 SDK 信息；不需要管理员权限，也不会修改系统 PATH。
命令中的 `ExecutionPolicy Bypass` 仅作用于该次 PowerShell 进程，不更改系统执行策略。

随后 `CherryDesk.cmd` 会使用项目内的 SDK 构建并启动程序；修改代码后再次运行即可。
准备好的 SDK 和缓存会留在本机，下次不必重新下载。即使电脑已经安装了系统 .NET，
当前脚本仍使用 `.tools` 中的便携 SDK，因此也应先运行上述准备命令。项目不依赖固定盘符，
不需要沿用公司电脑的 `D:\workspace\CherryDesk` 路径。

## 日常修改、测试与打包

所有命令都在包含 `README.md` 和 `CherryDesk.cmd` 的项目根目录运行。
开始重新构建或拉取更新前，通过托盘右键菜单“退出”结束旧程序；窗口右上角的关闭按钮只会隐藏到托盘。
可以用任意代码编辑器修改 `src` 下的 C# 和 XAML。双击 `Build-CherryDesk.cmd` 只构建，
双击 `CherryDesk.cmd` 构建并启动；运行回归测试则使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 test
```

测试使用模拟音频后端，不会切换本机真实音频设备。要获取其他电脑上传的代码，先提交或妥善保留
本机修改，再运行 `git pull`。如果更新包含 `global.json` 中 SDK 版本的变化，重新执行一次
前面的 `setup.ps1`，然后测试和启动即可；一般的代码更新不需要重装环境。

如果只想把程序带到其他电脑运行，可生成包含 .NET 运行时的便携包。这个步骤需要联网访问官方 NuGet 源：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 publish
```

生成结果在 `artifacts/CherryDesk-win-x64`。把整个文件夹复制到目标电脑，双击其中的
`CherryDesk.exe` 即可；只运行便携包的电脑无需 Git、SDK 或单独安装 .NET 运行时。
源码和测试、脚本、文档需要提交到 Git；`.tools`、`work`、`artifacts`、各项目的 `bin`/`obj`
以及本地设置和日志已被 `.gitignore` 排除，不会随 clone 下载。新电脑会生成自己的缓存和设置。
设置保存在实际运行程序的目录中，因此源码启动和便携包的电量阈值、悬浮窗设置也各自独立。

## 运行和使用

完成上述首次环境准备后，双击 `CherryDesk.cmd` 即可构建并启动。主窗口采用左侧功能导航和右侧
设置页，配色参考 [VS Code Dark Modern](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_modern.json)，
依次包含音频设备、设备电量、性能监控和关机助手；关机助手目前为适配说明页。窗口分别显示输出与麦克风
的当前默认设备和通信设备；在下拉框选择设备后立即切换。自动刷新和系统默认设备变化不会触发写入，
切换失败时恢复选择到系统实际默认设备，并沿用回读确认和失败回滚。
“同时切换默认通信设备”默认勾选，取消后只修改普通默认设备。

关闭窗口会驻留任务栏托盘。双击托盘图标打开窗口，右键菜单可直接选择
输入或输出设备，也可以退出程序。设备每三秒自动刷新，接入或拔出 USB
耳机后会更新。没有可用设备时禁用切换。音频组合预设、音频快捷键和
开机自动启动尚未实现。

切换的是 Windows 默认设备。游戏或语音软件若固定选用了具体设备，
可能需要改成“系统默认设备”；部分程序不会实时跟随系统切换。不能区分
两个插在同一模拟声卡接口且由系统呈现为同一个端点的物理耳机。

## 设备电量

启动后自动读取一次，每 5 分钟再次更新，无需开启功能开关；切到其他页或驻留托盘仍更新。
页面和托盘菜单都可手动更新，并发请求合并为一次读取。仅显示当前能够取得有效电量的设备，
查询不到、已断开、未知电量或不支持的设备不会作为占位项显示；全部为空时显示统一空状态。
更新时间显示为“刚刚更新”“5 分钟前更新”等相对时间，并在页面打开时自动推进。

首版读取 Windows 已暴露的传统蓝牙电量属性，以及 XInput 无线手柄电量，不主动搜索附近设备、
连接/配对设备或打开音频流。蓝牙通过地址和容器关联电量子节点，排除未连接设备的历史缓存。
该电量属性不是微软公开的稳定接口，因此读取实现单独隔离，缺失时跳过。暂不直接读取 BLE GATT，
也没有迈从 A7 等 2.4G 接收器的厂商协议适配，这些待家庭电脑实测后补充。
索尼 WH-1000XM5 需要验证本机蓝牙驱动是否暴露电量；Xbox 连接方式与电池类型也需要实测。

低电量阈值默认 20%，可输入 1–100，按 Enter 或离开输入框后保存到应用目录的
`battery-settings.json`。电量低于或等于阈值时，右下角托盘图标交替显示蓝色 C 与黄色感叹号，
不弹窗、不播放声音、不抢焦点。鼠标悬停可看低电量设备和数值，右键“设备电量”菜单显示完整列表。
点击提醒图标打开电量页；查看电量页后停止闪烁，但仍保留黄色标记，恢复正常电量后清除。
同一轮低电量不会因定时刷新反复闪烁；新的低电量设备或恢复正常后再次变低会重新提醒。
托盘图标如果被 Windows 收进折叠菜单，需要在系统设置中固定显示。

Xbox 的 XInput 接口只提供“即将耗尽、低、中、充足”四档，不转换为虚构百分比；
在低或耗尽时提醒，不受百分比阈值影响。设备数值可能分档或延迟，更新时间代表本应用查询时间，
不代表设备内部测量时间。回家可运行 `./scripts/dev.ps1 battery` 生成只读诊断
`work/battery-diagnostics.json`。诊断包含设备名称和蓝牙标识，保存在已被 Git 忽略的工作目录中。

## 性能悬浮窗

主窗口的“性能监控”页显示整机 CPU、所选显卡 GPU 和物理内存使用率，
内存同时显示已用与总容量（GiB）。页面右上角“启用监控”为独立总开关，
默认关闭。关闭时不会创建采集器、GPU 查询或周期采样定时器；关闭已有
监控时取消采样，等待正在进行的调用结束并释放采集器。界面清空旧数据，
隐藏悬浮窗。重新启用会创建全新采集器并重新预热，反复切换不会叠加线程。

启用后数据每秒更新，主窗口关闭到托盘或切到其他设置页时仍继续监控。
“显示悬浮窗”只控制是否显示，临时隐藏仍采集；要停止采集应关闭总开关。
Ctrl+Shift+F10/F11 不会在监控已关闭时偷偷启用采集。GPU 默认优先选择专用显存较大的硬件适配器，
也能手动选择；名称前的 GPU 编号为 DXGI 枚举顺序，不保证与任务管理器
的编号完全相同。部分机器会暴露同名的虚拟适配器，无有效计数时显示 `--`。

开启监控后，悬浮窗默认置顶、显示且锁定，鼠标会穿透到下方游戏。按
`Ctrl+Shift+F10` 显示或隐藏，`Ctrl+Shift+F11` 锁定或解锁；解锁后按住
悬浮窗拖动，完成后重新锁定。全局快捷键被占用时，主窗口会提示，仍可
使用主窗口或托盘菜单控制。“不透明度”越低越透明，“重置位置”移回主屏
工作区左上角；托盘中的重置还会重新显示悬浮窗。

监控总开关、悬浮窗显示状态、位置、锁定状态、不透明度和显卡选择保存在应用目录的
`overlay-settings.json`，采用临时文件替换方式写入。重启后恢复设置，
离屏位置在启动时调整回可见工作区。目录不可写时仍可使用，主窗口会
提示保存失败。显卡选择保存设备描述而非随重启变化的 LUID，在另一台
电脑找不到对应设备时自动回退。多个同型号适配器用枚举序号区分。
从 v0.2 升级时，旧的显示偏好会保留，但不会据此自动打开新的监控总开关。

悬浮窗为独立的 Windows 透明窗口，优先支持桌面、窗口化和无边框游戏。
独占全屏、各游戏的反作弊环境、多屏不同缩放率及家里 9070 XT 需要实测。
此版本不包含 FPS、温度或功耗。游戏内部数据和进程内存不参与采集。

## 开发环境

使用 C#、WPF、.NET 10 和少量 WinForms 托盘接口，当前只构建 x64。
固定 SDK 10.0.404，便携 SDK 放在 `.tools/dotnet`，不修改系统 PATH，
不需要安装完整 Visual Studio。`.tools/nuget` 保存包缓存，`work` 保存下载压缩包、
诊断结果和界面验证截图；这些本地文件可能占用较大空间，但不属于源码仓库。

`scripts/dev.ps1` 默认动作是 `run`，也支持 `build`、`test`、`diagnose`、`battery`、
`performance` 和 `publish`。调用时沿用上面的 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`
格式，只替换最后的动作名称。例如回家检查设备电量时，可以运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 battery
```

结果写入 `work/battery-diagnostics.json`。动作 `diagnose` 在 `work/audio-diagnostics.json`
输出真实音频设备和默认角色的只读快照；`performance` 连续采集六次，在
`work/performance-diagnostics.json` 保存数据和采集耗时。电量页为空可能表示设备不支持当前读取方式，
不一定是环境安装失败；迈从 A7 的 2.4G 协议目前尚未适配。

日常构建和测试不需要第三方 NuGet 包，`NuGet.Config` 默认清空源以便
离线还原；SDK 准备完成后，当前版本的普通构建和测试可以离线运行。
若提示 `Missing local SDK`，说明当前 clone 目录还没准备好便携 SDK，先执行 `setup.ps1`；
若下载失败，应先确认电脑能够访问微软下载站点或发布所需的 NuGet 源，再重新运行失败的命令。

已在 Win10 Pro 22H2 上完成构建、31 项回归测试、真实端点枚举、现有默认
设备写回检查及窗口/托盘启动验证。本机识别到两个输出端点，没有活动
麦克风；尚未进行不同实体设备之间的切换和听音测试。Win11 及家里的
音频设备还需要回家实测。实际可运行性与微软的操作系统维护支持范围不同，SDK 的官方支持
范围参见 [支持系统](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)。

## 实现与验证边界

`AudioSwitcher` 负责校验设备、切换所选角色、读取系统状态确认，并在
失败后尝试恢复各角色原来的设备。输入和输出相互独立。回归测试覆盖
中途失败、静默未生效、恢复失败、设备消失和通信设备选项。

`CoreAudioBackend` 枚举活动端点并读取友好名称。默认设备的设置使用
广泛用于音频切换工具的 PolicyConfig COM 接口；它不是微软承诺稳定的
公共设置接口，所以实现集中在单独模块，以便后续适配 Windows 更新。
程序只修改用户默认设备，不创建录音流、不修改游戏进程、不需要驱动。

CPU 从 `GetSystemTimes` 两次差值计算（内核时间包含空闲时间），物理
内存从 `GlobalMemoryStatusEx` 读取。CPU 口径为时间占用率，与任务管理器
按频率调整的处理器效用百分比可能不同；超过 64 个逻辑处理器的机器，
`GetSystemTimes` 有处理器组限制，本版本尚未针对这种硬件验证。
GPU 通过 DXGI 枚举，按 LUID 对应 PDH 的 `GPU Engine` 计数器；同一
物理引擎先合并各进程，再取最忙引擎，避免把不同引擎直接相加。计数器
使用语言无关名称，缺失、无效和预热中的数据均显示 `--`，不会伪装为 0%。
GPU 初始化失败后每 30 秒尝试恢复，其余指标继续更新。

公司 Intel UHD 730 上已经取得连续有效的 GPU、CPU、内存样本。
原生窗口验证包括 layered/transparent/noactivate 样式、锁定与解锁、
隐藏和恢复、不透明度。真实关闭验证会等待超过一个采样周期，确认采样
次数不再增长、活动采集器为零、旧快照清空且悬浮窗隐藏；回归测试也覆盖
关闭时的在途读取、重新开启、连续快速开关和旧设置迁移。
游戏内实际鼠标穿透与显示兼容性仍需实测。

出现错误时，日志写入应用目录下的 `logs/app.log`。诊断文件包含本机
设备名称和端点 ID。后续加速器模块需要在装有外星仔的家庭电脑上检查
客户端控件，并验证暂停状态；未确认成功前不会发起关机。

开发验证还可向程序传入 `--verify-defaults <json路径>`，逐个将现有角色
默认设备写回原值并读取确认；它不主动切到其他设备。`--smoke-test <png路径>`
会短暂启动窗口、生成托盘菜单并渲染自身 WPF 界面，再输出 PNG 和同名
JSON 状态报告后退出。截图为程序内容的渲染结果，不包含原生窗口边框。
`--overlay-smoke-test <png路径>` 会切到性能页、检查悬浮窗行为和采样，
输出主窗口 PNG、带 `-overlay` 后缀的悬浮窗 PNG、关闭状态和其他设置页
预览及 JSON 报告，并检查关闭监控后不再采样。启动检查
使用临时设置，不覆盖正常偏好；`--show-performance` 仅切换到性能页。
普通 `--smoke-test` 还验证默认启动时采样次数和活动采集器均为零。
`--battery-smoke-test <png路径>` 使用明确标记的模拟电量数据验证设备卡片布局，
不会据此宣称真实硬件已支持；`--show-battery` 打开设备电量页，正常运行不注入模拟数据。
